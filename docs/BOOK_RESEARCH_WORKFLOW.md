# 交易书籍 AI 深度研究工作流（下一本书复用版，2026-11-08）

> **目标**：上传一本交易书籍/研究报告后，产出可验收的深度、忠于来源的逐章解析、跨章概念/规则图谱、AI独立批判、完整待验证形式化案例索引、全书综合长评和单一验收入口。**默认不开发/运行回测实验室，不接真实行情，不许从合成数值审计推断收益。** 本规范由《缠论》五卷108课收尾流程归纳，适用于多卷、多版本、无图版、混排扫描版、作者/编辑注释冲突等书。

## 0. 先确定唯一目录与冻结输入

每本书使用一个稳定`book_slug`（例：`chanlun`，小写ASCII），一个最终验收入口：

| 内容类别 | 唯一规范路径 | 是否可复制到验收目录 |
|---|---|---|
| 用户提供的原PDF/EPUB/扫描件 | `ChineseBooks/<书名>/` 或 `EnglishBooks/<书名>/`（如属报告则`Reports/<书名>/`） | **不复制**；仅保留来源链接与校验值 |
| 正式逐章/节研究 | `analyses/books/<book_slug>/chapters/` | **不复制** |
| 书内跨章综述、概念与反驳 | `analyses/books/<book_slug>/volumes/`、`concepts/`、`critiques/`（确有内容时创建） | **不复制** |
| 原书物理页与版本索引 | `catalog/<book_slug>_*.json`、`catalog/books.yaml` | **不复制** |
| 按章节的原始来源证据 | `knowledge/evidence/<book_slug>_chapterNNN.json`（既有书的既定命名保持不动） | **不复制** |
| 结构关系图、版本冲突 | `knowledge/claims/<book_slug>_*.json`、`catalog/<book_slug>_rule_history*.json` | **不复制** |
| AI独立分析材料 | `ai_thoughts/ideas/<book_slug>_*.md` | **不复制** |
| 可复算但不触发实测的数学审计、现成脚本 | `experiments/protocols/<book_slug>_*.md`、`tools/<book_slug>_*.py`，需有真实使用价值 | **不复制** |
| 单一全书最终交付 | `deliverables/<book_slug>_acceptance/` | **唯一正式位置**：仅README、全书评述、逐章索引、形式化案例、验收报告、核验脚本、指向上表的清单 |

**禁止**：把`catalog/`、`knowledge/`、`tools/`、`tests/`和五卷原书直接镜像复制到`deliverables/`；为每个阶段保留另一套完整“备份/预览/临时”成果；将空`.gitkeep`放在已有文件的目录中；多路径放同一图表图片或OCR中间文本。Git历史已是版本保存机制，无须再在工作树内保存`-final-v2-copy`。

## 1. 接收与来源锁定（G0）

1. 只读清点用户实际上传的文件：唯一`source_id`，路径、SHA-256、字节数、实际PDF物理页数，语言、版本、卷次、授权/传播边界。
2. 使用原始PDF文本层优先、必要时自动OCR；扫描和图片页单独标注`text_layer`/`ocr_unverified`/`figure_unverified`，在质量不达标时`needs_review`，但**不要求用户逐页检查OCR**。
3. 自动索引目录/章节标题及PDF物理页，从1开始、与印刷页号分开；仅当原书证据存在时给出作者日期；收集“附录/后续问答/编者/重新汇编”独立归属与发表时间，未知为`null`。
4. **门槛**：没有来源文件指纹或章节定位，禁止进入细粒度断言；目录自动抽取不能冒充人工全书目录终审。

**最小成果**：一个`catalog/<book_slug>_source_index.json`；一个按章节映射源PDF物理页的目录；每卷/版本元数据和无法辨认页统计。

## 2. 章节/思想单元的七重解读（G1）

按章/节或可定位的独立思想单元写**一个规范文件**，每项尽可能包含：

- **来源与时序**：文件SHA、卷/章、原PDF物理页/图页、作者/后附注释/编者/转录版本、来源状态。
- **一：忠实复述**：区分作者事实性观察、术语定义、必要条件、定理声称、示例、修辞；尽量保留作者论证的强形式，但不能用AI推论补造原话。
- **二：逻辑审查**：列出隐含前提、充要混淆、反例、归纳外推、证据缺口。
- **三：数学/算法表达**：将能形式化的概念写为变量、量词、边界条件和状态/公式；不够明确时记`UNKNOWN`或“不可唯一形式化”，不自行发明作者规则。
- **四：市场与行为机制**：分开结构描述、预测、交易执行、组合风险、行为因素、档案史实。
- **五：跨学科和异源对照**：尽量给竞争解释；**不同作者、后期编者和AI观点共存，不做无根据的自动调和**。
- **六：可证伪命题**：每一条显式标`HYPOTHESIS`、源证据编号、变量/对照/反例/必要额外数据及`NOT_RUN`。
- **七：AI独立判断**：概括洞见、限制、可能有贡献的研究问题，不写成“作者证明”或“已赚钱”。

**输出**：`analyses/books/<book_slug>/chapters/<chapter_id>.md` + `knowledge/evidence/<book_slug>_<chapter_id>.json`。证据对象按`SOURCE`、`EDITORIAL`、`INTERPRETATION`、`INFERENCE`、`HYPOTHESIS`分类，每条包含`id`、`summary`、`pdf_pages`、`source_role`、`status`。不能用AI摘要覆盖原始证据或把未验证视觉数字当真实价格。

**验收门槛**：每章一份解读/一份证据、链接可定位到原卷和页、假说有自身稳定ID、在未读到正文时必须标`NEEDS_SOURCE_REVIEW`而非填空。

## 3. 图表、公式和时序审计（G2）

- 根据**是否影响结论**选择高价值原图核验，不默认全书每页OCR人工确认；原图未精确核实时，所有图中数字和线条结论标`figure_numeric_unverified`。
- 使用可分开引用的`figure_id` + 原卷SHA + 物理页 + 画面区域/子图索引；AI复原公式需标`AI_FORMALIZATION`，不要标为作者原有公式。
- 源数据可能出现多版本：原生文字、扫描、复刻、作者后发、编辑补注不得混为同一时间层。**“文中署时”不等于独立证明当时读者/市场一定可得**。
- 引用简短、以原创摘要+源页为主；未经授权不要额外复制原书全文或在公开仓库输出整页高清图。

**验收门槛**：有图但未审不阻止研究稿交付，但必须在章节、总评和交付矩阵标**未验证**；不能对重要图价做无凭据结论。

## 4. 跨章/跨卷全书理解（G3）

- 阶段性制作若干组章综述，最后构建**概念—条件—推论—反例—冲突**有向关系图，每条边有明确来源的章节/页。
- 后文否定、修正、独立再发与后期编辑质疑：建立`rule_version_id`、`source_role`、`source_displayed_at`及可得时间；冲突材料并存，不让后发版本自动覆盖早期版本。
- 标记“完整形式化尚缺什么”：递归终止条件、平局、价格精度、来源区分、已完成数据的确认时间、多级别含义。
- 写**一份全书AI独立长评**，不是逐章摘要的粘贴串联，必须包括：作者理论主线、版本演变、可论证/不可论证处、竞争解释、AI独立判断、待证命题、明确缺项。

**门槛**：全书概念至少能够回溯至唯一规范的源证据；不能用暂定图谱数目替代内容审核。

## 5. 所有未来可验证的形式化命题（G4：止于“给出例子”）

默认**只研究，不运行回测**。从全部章节的`HYPOTHESIS`条目完整提取，保持原始表述与证据编号；对不同类别分别制定有条件的未来验证协议：

| 研究类型 | 形式化建议 | 必须获得的额外证据 |
|---|---|---|
| 价格信号、交易策略 | `H0: ΔE[R_net(h)]≤0`；注明公式只是拟议研究合同 | 完整已冻结信号、当时可知价格、有效基线、费用及可成交性 |
| 结构/形态/唯一性 | `P_v(I_≤t)`、歧义集、结构重绘率、反例最小输入 | 完整文法、先验方向、冲突/等值裁决及源版本 |
| 事件时间、修订与跨周期 | `confirmed_at−extremum_at`，来源`received_at` | 原数据可知/收线/修订时间，不得事后回填 |
| 风险、仓位与执行 | 账本守恒、CVaR、最大回撤、成交率 | 现金、持仓、真实订单/盘口、市场制度（如T+1） |
| 行为/心理 | `E[rule_deviation|treatment]−E[rule_deviation|control]` | 行为问卷/过程记录/设计合理的对照样本 |
| 历史合约/新闻/监管 | 文书原件与断言之相符程度 | 实际合同/新闻/官方公告，价量无法替代档案事实 |

每条未来案例必须具有`case_id`、原书章节、claim ID、PDF物理页、原始假说、AI形式化（区分原作者公式）、数据需求、观察变量、事前基线、失败事件/负面控制、歧义阻断条件、`experiment_status=NOT_RUN`。没有完整前提时只列**待检验**，不能暗示结果已证实。

**门槛**：所有显式假说均能在案例清单中找到，且每条仅有一份权威机器可读记录；人工浏览表可以是该记录的索引，但不得再抄出多套重复正文。跨章案例要标明所引用的源假说，并避免“110条+36个=146个已知盈利策略”的错误表述。

## 6. 全书交付与单目录验收（G5）

交付目录`deliverables/<book_slug>_acceptance/`必须能一眼找到：

1. `README.md`：验收导航（只放最终成果，给规范源目录链接）。
2. `00_REVIEW/FINAL_BOOK_SYNTHESIS.md`：有深度的独立综合长评。
3. `00_REVIEW/CHAPTER_ACCEPTANCE_MATRIX.md`：所有章节到原文、解读、证据的可用链接。
4. `03_formal_cases/ALL_PROSPECTIVE_CASES.json`和`README.md`：未来需要验证的完整索引；必要时生成不重复正文的浏览表。
5. `00_REVIEW/CANONICAL_FILE_MANIFEST.json`、`audit_acceptance.py`与`ACCEPTANCE_REPORT.md`：**检查规范原文件的位置和内容SHA，不复制原件**。
6. `docs/BOOK_RESEARCH_WORKFLOW.md`为仓库级通用规范（**不**在每本书包内重复拷贝）。

**打包原则**：Git仓库只保存一份原始PDF与一份阶段产物。若需要下载完整离线ZIP，由CI从规范路径**临时组装一次**（内含原PDF、解读、证据、终审材料及必需图谱），作为30天有效的GitHub Actions artifact，**不得把打包结果再提交仓库**。离线ZIP携带真实文件，不是只有外链；仓库里只保留单份原件。

**验收门槛**：源SHA可比对、章节全覆盖、假说一一绑定原证据、文档链接可解析、历史来源/编辑争议存在、不存在内容相同的成果副本，真实行情结果仍为`NOT_RUN`（除非用户另行明确授权）。

## 7. 清理和收官（G6）

- 先建立**规范路径使用清单**，以Git blob SHA检索字节完全相同的多路径，确认**哪些是同源备份**、哪些属于逻辑上不同的正式产物；保留规范一份，删除重复的验收目录树、空临时索引、已占用目录的`.gitkeep`。
- 不盲删含独立解释、证据或自动化测试的研究文件；确有不同内容的文件即使都叫“报告”也应保留或合并后再删。实在难判定的遗留文档标`archive_to_review`而非无依据删除。
- 修改所有被删副本的Markdown链接/验证程序，交由CI检查；
- 最后冻结全书综述、验收总表及未来验证案例，合并后不再继续扩建该书的回测实验室。修订时保留Git历史，不再创建`copy2`文件。

## 8. 下一本书执行顺序（最短主线）

```text
书源登记与SHA → 目录和来源层 → 自动文字/图表质量盘点
→ 逐章七重深度解读 + 一一对应证据 → 跨章概念与冲突关系
→ 全书独立综合评论 → 全部显式待检验的形式化案例（NOT_RUN）
→ 单目录索引、规范文件校验、去重 → 下载时临时组装ZIP → 完成验收
```

**交互原则**：AI承担文件读取、OCR自动质量评估和批量验证，不要求用户逐页自己点图校对；只在存在真正冲突和不可消歧原书信息时保留`needs_review`，把缺项交付为可见报告。用户一句“继续下一本书”即按照上述门槛执行；除非明确改变要求，**不会自动开始A股回测、实盘、自动交易或无限推进研究实验室**。

## 9. 《缠论》案例经验

- 不应把五卷PDF和约600份研究过程文件再复制一套进验收目录；这会让一个仓库出现两个同名真本，造成后续链路和合并偏差。
- 独立来源版本、作者与编辑异议、PDF物理页、最终确认时间不混淆，比堆叠大量“已通过测试”更关键。
- 108课形成了110条显式假说、36个跨课例子：它们是未来研究问题，不是已经完成的实证成果。
- 全量图表精确价格校验、所有后附资料的出版时间核查未完全完成，应在全书终审中明确列出而不是让用户自行校验每一页。
- 正式验收文件夹只保存**最终交付和引用索引**；所有原始书源、研究解读、证据和可复用工具留在各自规范路径，CI临时打包提供完整离线文件。
